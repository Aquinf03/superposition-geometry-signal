Caveats

Geometry beside loss is useful when it moves with something real. It is not a ground-truth entanglement meter. Full notes: root failure_notes.md.

Flat signal

SituationWhat you see
Wrong / inactive layerCurves barely twitch while loss falls.
Coarse cadenceSparse points look constant.
Tiny / saturated bankMetrics stuck near floor or ceiling.
Already-collapsed regimeLate spectral ≈ 0 and stays there.

Check: python experiments/validate_training_geometry.py --run-dir …

Misleading signal

  • Small corpus overfit looks like structure. Geometry tracked the fine-tune; that is not general representation learning by itself.
  • Late-layer collapse washes cross-feature gaps. Prefer mid layers for structure claims.
  • Bank relative. Location probes make location features look coherent. Freeze probes in the sidecar.
  • Control train-bank ≠ held-out. Optimizing the control bank can look like success while held-out geometry barely follows. Run validate_control_geometry.py.
  • Edit demos ≠ training claim. ROME / edit-time nudges show geometry moves when weights change. They are thin existence proofs.

How to read a run

  1. Loss + multi-layer plot first.
  2. Ask which layer phase moved (collapse vs mild drift).
  3. Diff selected features at mid layers.
  4. Run training validate; if control is on, run control validate + held-out claims.
